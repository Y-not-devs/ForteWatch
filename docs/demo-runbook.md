# Demo runbook

## До показа

1. Убедиться, что локальный Ollama запущен и модель `qwen3.5:4b` уже установлена. Подготовку модели сделать заранее: если весов нет, `scripts/prepare_model.py` скачает их.
2. Из корня проекта выполнить `npm run dev` и открыть `http://localhost:5173`.
3. Ввести значение `ANALYSIS_API_KEY` из локального `.env`. Не вставлять ключ в слайды, чат или публичную запись экрана.
4. Подготовить один короткий `.mov` с видимым событием. Не запускать весь набор из 42 видео во время презентации.

## Сценарий показа

1. Объяснить задачу: локально подсветить проверяющему возможные визуальные признаки нарушения кассовой дисциплины.
2. Загрузить ролик и показать ход анализа. Видео передаётся локальному сервису и анализируется локальной моделью Qwen; облачный AI не используется.
3. Открыть результат: вердикт, найденное событие, кликабельный таймкод, стоп-кадр и ссылку на нормативный источник.
4. Перейти по таймкоду в видеоплеере и сравнить событие с доказательным кадром.
   Для показа восстановления обновить страницу, заново ввести API-ключ и нажать «Восстановить задание». ID сохраняется только в текущей вкладке; ключ не сохраняется. Стоп-кадры доступны сразу, исходное видео для перемотки нужно выбрать заново. «Забыть задание» убирает сохранённый ID из вкладки, но не удаляет результат на сервере. Если задание больше недоступно, потребуется новый анализ.
5. Подчеркнуть, что это инструмент поддержки проверки: результат модели — признак для рассмотрения, а не доказательство нарушения или юридическое заключение.

## Если демонстрация не сработала

- При ошибке подключения проверить, что Ollama и приложение запущены; не запускать повторно весь benchmark.
- Если браузер не воспроизводит кодек MOV, показать JPEG-доказательства и таймкоды: они отображаются независимо от поддержки видеокодека браузером.
- Подготовить локальную запись экрана успешного показа как резерв.

## Как сообщать качество

В `docs/evaluation.md` сохранена оценка baseline на предоставленной development-выборке из 42 видео: 23/42 совпадения (54,76%), 14 ложных срабатываний, 5 пропусков, 0 failed jobs. Это не независимая проверка и не оценка качества на новых камерах. Не представлять результат как автоматическое подтверждение нарушения.
