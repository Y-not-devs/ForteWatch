# Эксперименты и калибровка детектора

В продуктовой конфигурации используется двухэтапный пайплайн на базе локальной модели `Qwen3.5-4B` (контакт-листы предложений по 8 кадров + независимая верификация по 3 увеличенным кадрам доказательств). Ниже приведены результаты исследованных альтернативных конфигураций и причины выбора итогового baseline.

## 1. Сравнение вариантов верификатора на подвыборках

Два альтернативных варианта проверялись на диагностических подвыборках и были отклонены, так как приводили к росту пропусков нарушений (FN), что противоречит приоритету задачи (недопустимость пропуска нарушений):

| Вариант пайплайна | Видео | Baseline (TP / FN / FP / TN) | Эксперимент (TP / FN / FP / TN) | Recall (Baseline) | Recall (Эксперимент) |
| :--- | ---: | :---: | :---: | ---: | ---: |
| Отдельные изображения без контакт-листа + строгая проверка предикатов | 14 | 6 / 1 / 4 / 3 | 3 / 4 / 4 / 3 | 85.71% | 42.86% |
| Baseline-предложения + строгий предикатный верификатор | 9 | 3 / 1 / 3 / 2 | 0 / 4 / 1 / 4 | 75.00% | 0.00% |

Строгий предикатный верификатор снижал число ложных срабатываний, но отсекал реальные нарушения из-за перекрытий мелких объектов при съёмке сверху.

## 2. Полноразмерный эксперимент с расширенным временным окном (42 видео)

Проверялась гипотеза о передаче 9 равномерно распределённых кадров (вместо 3) в запрос верификатора для длящихся правил (`cash_not_secured` и `cashier_leaves_client`):

| Метрика | Итоговый Baseline (3 кадра верификации) | Расширенное окно (9 кадров верификации) |
| :--- | ---: | ---: |
| **Обработано успешно / сбоев** | **42 / 0** | 42 / 0 |
| **TP / TN / FP / FN** | **17 / 6 / 14 / 5** | 17 / 4 / 16 / 5 |
| **Точность вердикта (Accuracy)** | **54.76%** | 50.00% |
| **Precision / Recall / F1** | **54.84% / 77.27% / 64.15%** | 51.52% / 77.27% / 61.82% |
| **Максимальное время анализа** | **73.297 с** | 98.360 с |
| **MAE таймкода (на 17 TP)** | **9.527 с** | 8.422 с |
| **Таймкод в пределах ≤ 2 с** | **7 / 22** | 9 / 22 |

**Вывод**: Увеличение числа кадров верификации с 3 до 9 замедлило пиковое время обработки с 73.3 с до 98.4 с и добавило 2 ложноположительных срабатывания (`Х-10` и `Х-16`) без прироста полноты (Recall остался 77.27%). В результате в рабочей ветке зафиксирован более точный и быстрый 3-кадровый верификатор.

## 3. Диагностическое трассирование

Для анализа решений модели поддерживается опциональная локальная трассировка (`ANALYSIS_DIAGNOSTICS=1`). При включении воркер записывает в `backend/data/analysis/<job_id>/diagnostics.jsonl` таймкоды сэмплирования, кандидатов первого этапа, срабатывания дедупликации и решения верификатора без сохранения изображений или ключей доступа.
